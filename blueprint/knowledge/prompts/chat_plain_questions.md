下面是一份 Agent 产品方案里列出的「待确认问题」。它们要拿给提出这个产品想法的人看，这个人不懂技术。请逐条处理。

## 待确认问题（前面的数字是编号）
{questions}

## 每一条要给出
- index：原编号。
- audience：
  - user：提出想法的人能回答的事：给谁用、要做到什么、不要什么、愿意花多少钱和时间、内容和规则从哪来、出了问题希望怎么处理。
  - dev：只有工程师能判断的事，或者只是对方案本身的技术备注（组件选型、特征标签、字段、实现路径、模型与服务怎么选）。
  - 拿不准时选 user。
- plain：
  - user 的条目：改写成大白话的问题。不用术语，必须用就顺手解释；原问题里塞了好几个小问，只保留最关键的一两个；可以在后面给一个回答示例；不超过 80 字。
  - dev 的条目：用一句话说明这是什么待定事项，不超过 60 字。
- priority（只给 user 的条目）：1 = 不回答就没法动手，或者会让方案大改（比如给谁用、核心功能、绝对不能做的事）；2 = 重要，但可以先按常见做法往下走；3 = 细节，开发时再定也行。1 不要超过 5 条。
- duplicate_of：需求拆解和架构设计各列了一遍问题，常有两条问的是同一件事、只是说法不同。遇到这种情况，在后面那条填前面那条的编号，界面上只问一次；不重复就不填这个键。
- 不改变原意，不编造原问题里没有的事实，每一条都要输出（重复的也要输出）。

## 输出 JSON 结构
{{"items": [{{"index": 0, "plain": "……", "audience": "user", "priority": 1}}, {{"index": 5, "plain": "……", "audience": "user", "duplicate_of": 0}}]}}
