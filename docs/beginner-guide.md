# 纯小白入门指南 —— 只有一个想法也能开始

> 你是 AI 产品经理，手上只有一个模糊的想法（甚至只有一句话），还没有 PRD？
> 这份指南就是给你的。它用大白话，一步步带你**把想法问清楚**，最后产出一份能交给 AI 继续推导的 PRD。
>
> 读完这份指南，再回 [BLUEPRINT.md](../BLUEPRINT.md) 走五步推导。

---

## 先认清一件事

这个项目（叫它「系统」也行）做的事情是：

> 你给它一个**想清楚的需求**，它帮你推导出架构、组件选型、代码骨架，直到一个能跑的产品。

但它有个前提：**你的需求得先想清楚**。这份指南就是帮你做这件事的——在你还没有 PRD、只有一句话想法的时候，先把问题问明白。

---

## 一、黑话对照表

这个项目里有些词，你可能是第一次见。先看这张表，后面就不会卡住：

| 黑话 | 大白话 | 例子 |
|---|---|---|
| Agent | 一个能自己调用工具、一步步完成任务的 AI 程序 | 一个会自己查数据库、写报告、发邮件的助手 |
| Harness | AI 外面的那层「外壳/载具」——你写的代码 | AI 是大脑，Harness 是给它装上手脚的外壳 |
| 工具（Tools） | AI 能调用的外部功能 | 读文件、查天气、发邮件、调 API |
| 知识（Knowledge） | AI 必须提前知道的领域资料/规则 | 产品文档、行业规范、术语表 |
| 观察（Observation） | 怎么确认 AI 做对了没 | 看日志、看结果、看状态变化 |
| 行动（Action） | AI 实际执行动作的形式 | 调 API、跑命令、发消息 |
| 权限（Permissions） | 哪些事 AI 能做、哪些要你批准 | 只读数据可以自动，删数据要确认 |
| PRD | 产品需求文档，把想法写清楚的一页纸 | 「给谁用、做什么、怎么算成」 |
| 组件 | 预先写好的、可复用的功能模块 | 记忆模块、定时任务模块、权限模块 |

> 你现在**不需要背下来**，只需要知道：遇到看不懂的词，回来看这张表。

## 二、三步访谈法：把想法问清楚

不要一次回答 8 个问题。分 3 个阶段，**每阶段只问 2~3 个，答完再进下一阶段**。

先记住三条心态，比答案本身更重要：

1. **答案可以很粗糙**，先写下来，后面随时改。
2. **答不上来不丢人**，每个问题下面都有「答不上来怎么办」。
3. **不硬编**：真不知道的，就标「待确认」，别自己脑补一个假答案。

每个问题都配了：**为什么问 + 怎么回答（例子）+ 答不上来的兜底**。

---

### 阶段一：把「想法」讲清楚（定方向）

**开场：用一句话说清你的想法**

套这个模板：

> 我想做一个给【谁】用的东西，帮他们解决【什么痛点】，最后他们能得到【什么】。

如果一句话都填不满这三个空，说明想法还没成型——没关系，继续往下答，答着答着就清楚了。

---

#### 问题 ①：给谁用？解决什么痛点？

- **为什么问**：不知道给谁用，后面所有决策都是空中楼阁。
- **怎么回答（例子）**：「给要读英文论文的人用，帮他们省掉逐段复制翻译、逐词查术语的时间。」——「谁 + 痛点」说清楚即可。
- **答不上来？** 反问自己：如果没有这个工具，现在大家是怎么凑合的？凑合得越痛苦，痛点越真。

#### 问题 ②：现在没有它，大家怎么凑合？

- **为什么问**：验证这是不是真需求。凑合成本很低 = 大概率是伪需求。
- **怎么回答（例子）**：「现在把 PDF 一段段复制到翻译软件里翻，再手动查专业术语，一篇 30 页论文要搞两三天。」
- **答不上来？** 说明你可能还没验证过痛点。先别急着做，去找 3 个真实用户聊聊再回来。

#### 问题 ③：做成什么样，算「成了」？

- **为什么问**：没有成功标准，做完了也不知道好不好。
- **怎么回答（例子）**：「一篇 30 页论文，从上传到能顺畅阅读，不超过 5 分钟；术语解释准确率 90% 以上。」
- **答不上来？** 先定一个最朴素的标准：「我每周愿意用它读完 N 篇论文」，N 是多少？

---

### 阶段二：把「流程」想清楚（定闭环）

#### 问题 ④：用户一次完整操作，从哪到哪？

- **为什么问**：这是产品「一次交付长什么样」，一切功能的骨架。
- **怎么回答（例子）**：「用户上传 PDF → 系统翻译成中英对照 → 自动标出术语并解释 → 用户阅读、收藏术语 → 术语进个人词库。」
- **答不上来？** 从「用户点开工具的第一下」数到「用户满意关掉的那一下」，把中间每一步列出来。

#### 问题 ⑤：中途需要调哪些「外部东西」？

- **为什么问**：AI 不能凭空干活，得知道它要伸手去拿什么。大白话就是——「它干活需要碰哪些数据/系统/接口？」
- **怎么回答（例子）**：「要读 PDF 文件、要调 DeepSeek 翻译接口、要把论文和术语存起来（本地数据库）。」
- **答不上来？** 先想「输入是什么、输出存哪」，中间要碰的往往就是三样：文件、某个 AI 接口、一个存数据的地方。

#### 问题 ⑥：有什么绝对不能做？

- **为什么问**：红线比功能更重要，先划边界再给自由。
- **怎么回答（例子）**：「不能把用户论文上传给不明第三方；不能删除用户的术语库；不能编造术语解释。」
- **答不上来？** 先定三条最朴素的：不动用户数据、不删东西、不说假话。

---

### 阶段三：把「风险」想清楚（定底线）

#### 问题 ⑦：中途出错、卡住、答不上来，怎么办？

- **为什么问**：真实产品一定会出错，想好退路才敢上线。
- **怎么回答（例子）**：「PDF 解析失败 → 提示用户换一份或手动粘贴文本；翻译接口超时 → 自动重试 3 次，仍失败就提示稍后再试。」
- **答不上来？** 通用兜底：**出错就给用户一个明确提示 + 一个能重来的入口**，别让用户卡死在黑屏。

#### 问题 ⑧：哪些专业知识是模型必须懂的？从哪来？

- **为什么问**：AI 是通用大脑，领域知识（术语、规范、规则）得由你喂给它。
- **怎么回答（例子）**：「需要 AI 领域的术语库（如 LLM、attention、transformer），来源是论文里自动提取 + 跨篇积累。」
- **答不上来？** 问自己：这个领域里，有没有「外行看不懂、但行内人必须知道」的东西？有，那就是领域知识。

## 三、完整范例：从一句话到 PRD

下面用真实例子走一遍——「我想做一个帮人读英文论文的工具」。

### 第 0 步：一句话想法

> 我想做一个帮人读英文论文的工具。

### 阶段一（定方向）

- **① 给谁用？** 需要读英文论文的人（本人为主），AI 领域为主。
- **② 现在怎么凑合？** 一段段复制到翻译软件，术语逐个查，一篇 30 页论文要两三天。
- **③ 怎么算成？** 30 页论文从上传到能读 ≤ 5 分钟；术语解释准确、能积累。

### 阶段二（定闭环）

- **④ 完整操作**：上传 PDF → 中英左右分栏对照 → 术语自动标色 + 解释 → 收藏术语 → 进个人词库、跨篇积累。
- **⑤ 外部依赖**：读 PDF、调 DeepSeek 翻译、存论文和术语库（本地数据库）。
- **⑥ 红线**：不上传用户论文给第三方；不删用户词库；不编造术语解释。

### 阶段三（定底线）

- **⑦ 出错怎么办**：PDF 解析失败 → 提示手动粘贴；翻译超时 → 重试 3 次再放弃并提示。
- **⑧ 领域知识**：AI 领域术语库，靠「论文自动提取 + 跨篇积累」。

### 澄清后的 PRD（一页纸）

| 维度 | 内容 |
|---|---|
| 目标 | Web 工具：把英文论文变成「中英左右对照 + 术语高亮解释」的阅读材料，帮人快速读论文 |
| 用户 | 需要读英文论文的人（本人为主，AI 领域为主），单人本地使用 |
| 核心闭环 | 上传 PDF → 翻译对照 → 术语提取/高亮/解释 → 收藏 → 跨篇术语库 |
| 交付物 | 中英分栏阅读页 + 术语卡片（中文释义 + 英文原义 + 例句 + 相关概念） |
| 边界 | 不上传用户论文、不删数据、不编造解释 |
| 约束 | 模型用 DeepSeek；术语解释要能人工校对 |

> 到这一步，你的想法已经从一句话变成了一份**可推导的 PRD**。接下来把它交给 AI，按 [BLUEPRINT.md](../BLUEPRINT.md) 的五步 SOP 继续：拆解 → 建模 → 选型 → 架构 → 代码。

## 四、下一步

1. 照「三步访谈法」把你的想法过一遍，产出上面那样的一页纸 PRD。
2. 把这份 PRD + [BLUEPRINT.md](../BLUEPRINT.md) 一起交给 AI（或直接用它继续对话）。
3. AI 会按五步 SOP 先给你**架构方案**，你确认后再生成代码。

**记住一条铁律：先方案，后代码。方案没确认前，别急着让 AI 写代码。**
