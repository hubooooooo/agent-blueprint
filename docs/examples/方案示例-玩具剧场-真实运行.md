## 产品定位（一句话）

**玩具剧场**：给家长用：拍一张玩具合影，AI 识别照片里的玩具并生成一份可亲子共演的互动剧情脚本（角色分配、场景搭建、分幕、对话、家长引导话术），让旧玩具翻新，也帮家长读懂孩子、一起玩。

## Step 2 · 领域建模（映射 Harness 五要素）

| 要素 | 内容 |
|---|---|
| **工具** | 玩具合影上传入口：接收家长拍摄的单张玩具合影，仅存在会话内存或临时文件，默认不写入持久化存储；多模态图像识别接口：对合影做玩具识别，输出玩具清单（名称、外形、可扮演角色候选）；儿童适龄内容规范知识库：按孩子年龄段检索暴力、恐怖、成人、危险模仿等红线条目与适龄判定标准；玩具剧情范式库：检索角色分配、场景搭建、分幕、对话、家长引导话术的剧情结构模板；生成脚本适龄审核接口：对脚本全文做红线与适龄检测，返回通过或不通过及违规条目；脚本渲染与展示：把结构化脚本按角色分配、场景搭建、分幕、对话、家长引导话术五段呈现给家长 |
| **知识** | 儿童适龄内容规范：暴力、恐怖、成人、危险模仿四类红线清单与适龄判定条目（输入明确要求此类领域知识库）；玩具剧情范式库：角色分配、场景搭建、分幕、对话、家长引导话术的可复用剧情结构模板；脚本交付物结构规范：一份脚本必须齐备角色分配、场景搭建、分幕、对话、家长引导话术五部分；照片隐私处理规则：照片默认不保存，仅本次会话内使用，交付后清除 |
| **观察** | 识别结果是否覆盖合影中的玩具，玩具名称与照片数量是否一致；脚本是否齐备五段结构，且角色分配里的角色都来自识别出的玩具清单；适龄审核的结论与违规条目，是否出现拦截或重写；照片临时数据是否已按默认不保存策略清除；家长对脚本的采纳、要求重生成或放弃的反馈状态 |
| **行动** | 通过对话式界面把脚本全文回传家长阅读与复制；在脚本交付前经钩子执行适龄审核，不合格则阻断并退回重写；调用适龄审核接口并接收通过或不通过的结论；清理照片临时数据（删除动作），并确认已删除；根据家长反馈触发一版重新生成 |
| **权限** | 默认拒绝：把照片写入持久化存储或上传至云端，除非家长显式同意（照片是否上云仍待确认）；默认拒绝：生成暴力、恐怖、成人、危险模仿内容，由钩子在交付前硬拦截，不产出给家长；需要审批：跨会话保存孩子的年龄段与偏好玩具（二期个性化），需家长显式授权；允许：只读访问儿童适龄内容规范与玩具剧情范式库知识库；默认拒绝：描述照片中的人脸、家庭成员与环境细节，只允许描述玩具本身 |

| `load_skill` | 技能名称，取值为儿童适龄内容规范或玩具剧情范式库 | 对应 SKILL.md 全文（红线清单、适龄判定条目、剧情结构模板） | 只读读取本地知识库文件，无写入 | allow | ⑤能力集成层 |
| `check_content_safety` | 脚本全文与孩子年龄段（若家长未提供则该字段为空） | 审核结论：通过或不通过，附违规条目与修改建议 | 调用适龄审核接口，不写入任何持久化存储，仅记一条审核日志 | allow | ⑤能力集成层 |
| `render_script` | 结构化脚本对象（角色分配、场景搭建、分幕、对话、家长引导话术） | 家长可读的五段式脚本文本 | 无外部副作用，不访问网络也不写盘 | allow | ②产品层 |
| `purge_session_photo` | 照片引用标识 | 删除结果确认（已清除或未找到） | 删除本次会话的照片内存缓冲区与临时文件，不可恢复；由交付后钩子自动触发，不经家长确认 | allow | ⑥数据层 |
| `archive_photo_to_cloud` | 照片引用标识与存储目标 | 被拒绝的提示信息 | 无（权限层硬拒绝，不执行上传） | deny | ⑥数据层 |

### 系统提示词草案

```
你是「玩具剧场」的亲子剧情脚本导演，为家长服务，孩子是最终体验者。
规则：1) 角色只能取自 recognize_toys 识别出的玩具，不得虚构照片外的人或玩具；2) 绝不生成暴力、恐怖、成人、危险模仿内容，不出现刀具、火源、高处攀爬等可模仿动作；3) 脚本须经 check_content_safety 审核通过才可交付，不通过就改写重审；4) 照片默认不保存，只描述玩具，不描述人脸、家人与环境细节；5) 家长未给年龄段时按更保守标准生成并请其补充；6) 必须齐备角色分配、场景搭建、分幕、对话、家长引导话术五段，引导话术要具体成家长能说出口的句子。
工具：upload_toy_photo、recognize_toys、load_skill、check_content_safety、render_script、purge_session_photo，archive_photo_to_cloud 默认禁止。
知识目录：儿童适龄内容规范、玩具剧情范式库。
```

### 上下文与记忆策略

单次会话（一次拍照到一份脚本）内保留：照片识别出的玩具清单、已加载的儿童适龄内容规范与玩具剧情范式库文本、脚本草稿、审核结论与改写轮次；不保留原始图像。知识库按需经 load_skill 加载，未用到的不进上下文。会话结束或脚本交付后调用 purge_session_photo 清除照片数据。跨会话默认不持久化任何内容；记住孩子年龄段与偏好玩具属于二期（s09），需家长显式授权后才写入，且只存年龄段与玩具偏好字段，不存照片与对话原文。单次闭环未出现长会话与大量工具输出，暂不做上下文压缩（s08 已放弃）。

### 安全边界与降级策略

- 照片识别失败或超时 → 不猜测玩具清单，请家长重拍或手动输入玩具名称，并说明本次不生成脚本（重试次数假设 1 次，待确认）
- 适龄审核接口不可用 → 默认不放行，交付降级为「审核服务暂不可用，请稍后重试」，绝不交付未审核脚本
- 脚本触发红线 → 钩子在交付前阻断并退回重写，改写次数有上限（假设 2 次，待确认），仍不通过则只返回安全提示与可调整方向，不输出脚本
- 模型幻觉（脚本里出现照片中没有的玩具或人物）→ 交付前用识别清单校验角色来源，超出清单则重新生成
- 越权（请求调用无权限工具、尝试把照片上云或写入持久化存储、尝试读取其他家庭或其他会话的照片与脚本）→ 权限层默认拒绝并写审计日志，不返回任何数据，仅提示家长操作不被允许
- 生成超时 → 明确告知本次未完成并建议重试或减少玩具数量，不返回半成品脚本（时延阈值待确认）
- 家长输入含孩子姓名、学校等身份信息 → 不在日志与脚本中回显，仅保留年龄段这类非识别性字段

### 可观测性

- 日志：每次工具调用的入参摘要、耗时与结果状态（照片只记标识，不记内容）；权限判定记录：工具名、命中规则、allow/ask/deny 决策与原因；适龄审核记录：审核结论、违规条目、改写轮次；照片生命周期记录：接收时间与清除确认时间
- 指标：单次会话端到端耗时与各工具耗时分布；脚本一次通过审核率与平均改写轮次；红线拦截次数按违规类型（暴力、恐怖、成人、危险模仿）分布；照片临时数据清除成功率；识别失败率与家长重拍率
- 轨迹：每次会话以一条轨迹记录：用户输入摘要、每轮模型响应中的工具调用与参数、工具返回摘要、权限与审核钩子的触发结果，按时间顺序落库，照片内容不入轨迹，只记引用标识与清除状态。

### 技术栈与部署形态

第一版为单进程 Python 服务：①交互层为移动端网页（H5）拍照上传与脚本阅读页（交互形态同步或异步待确认），②产品层负责脚本五段式组装与渲染，③Agent 编排层为单一 agent loop 装配 s03 权限、s04 钩子、s07 技能加载，④模型层调用多模态模型做玩具识别与文本模型写脚本（模型来源与具体型号待确认），⑤能力集成层封装识别、审核与 load_skill 知识库读取，⑥数据层只做会话内存与临时文件、无照片持久化，⑦基础设施层为单机容器部署。配置与密钥外置到 .env（模型 API Key、审核接口地址、知识库目录路径），不硬编码，用一条命令 python -m toy_theater 启动。

## 独立审稿意见

- 结论：✅ 通过（82 / 100），设计稿共 1 版
- 总评：方案整体忠于原始输入，事实条目基本都有出处，边界（内容红线、照片不保存、适龄审核）都落到了权限、钩子与降级设计上，可运行、可容错、可观测、可测试四项覆盖较实。主要缺口在可度量（缺对齐 PRD 的成功指标）、要素与工具清单的局部不对齐（再生成、幻觉校验无承载工具）、以及「同步秒级响应」这一未经输入支持的假设。建议补齐后的整体质量可达可交付水平。
- [medium] components.s11 后台任务：放弃理由写明「识别照片与生成脚本均为秒级到分钟级内的同步响应」，但输入明确「交互形态还没定」，也未给时延；该假设未标注待确认，却直接支撑了组件弃用决策，若生成实际为分钟级则 s11 与 s16 的结论需要翻转。
- [medium] design.observability / design.open_questions：「可度量」只给出端到端耗时、审核通过率、拦截次数等运维指标，缺少对齐 PRD 的产品成功指标（如复玩率、家长满意度）及其采集口径；虽已列入 open_questions 标为待确认，但验收标准中的「可度量」尚未闭环。
- [medium] elements.action / elements.observation 与 design.tool_list 的对应：要素中有「根据家长反馈触发一版重新生成」和观察项「家长采纳、要求重生成或放弃的反馈状态」，但工具清单没有对应的再生成工具，观察项也没有落库字段或采集点，五要素与工具清单不完全对齐。
- [medium] design.security_and_degradation 幻觉降级：「交付前用识别清单校验角色来源，超出清单则重新生成」没有落到具体工具或钩子上，system_prompt 只写了「角色只能取自 recognize_toys 识别出的玩具」，缺少可执行的校验步骤与不合规判定口径，测试用例中的幻觉测试因此没有对应实现依据。
- [medium] design.security_and_degradation 隐私：check_content_safety 若为云端审核接口，脚本全文（可能含家长输入的孩子称呼、家庭信息）外发的数据边界与脱敏策略未定义，也未进入 open_questions，与「照片默认不保存」「不回显身份信息」的隐私约束存在缺口。
- [low] elements.knowledge 与 design.tool_list：knowledge 要素里的「脚本交付物结构规范」和「照片隐私处理规则」没有对应的知识库文件或加载路径——load_skill 的取值只列了儿童适龄内容规范与玩具剧情范式库两项，这两条知识无承载工具。
- [low] design.tech_stack_and_deployment：写明了单进程 Python 服务、容器部署与一条命令启动，也提到配置外置到 .env，但未提及启动文档与 .env 示例文件、依赖安装步骤，验收标准「有启动文档」未明确覆盖。
- [low] facts.goal：goal 的 source 是输入原文中明确陈述的目标，status 却整体标为「待确认」；应拆成「目标（明确）」与「可量化成功标准（待确认）」两条，否则状态与出处自相矛盾。
- [low] design.tool_list upload_toy_photo / purge_session_photo：upload_toy_photo 的 permission 标为 ask，但上传是家长主动发起的动作，ask 语义与触发方不符；另外仅在「交付后」触发清除，识别失败、审核始终不通过、会话中断等路径下是否仍执行 purge 未说明。
